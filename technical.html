01

The experience

REACT 19 / TANSTACK START+

Recruiters manage jobs, resumes and evaluations. Candidates use a separate interview portal for verification, voice responses and video capture. TanStack Start provides routing and server rendering; React supplies the interactive interface.

Recruiter surface
Archive explorer, semantic search, question bank and evaluator workbench.
Candidate surface
Magic-link entry, hardware checks, active liveness and a conversational interview.
Platform guide pp. 2, 6–8 · Applicant guide pp. 3, 6
02

The orchestrator

BACKEND FOR FRONTEND / NITRO+

The Backend for Frontend (BFF) is the server-side boundary between the browser and private services. TanStack server functions validate the session, prepare requests and return typed results. Nitro packages the application as a standalone server bundle.

Session boundary
Firebase Admin verifies the session cookie before protected operations.
Service boundary
Google IAM tokens are scoped to the destination service. Credentials remain on the server.
Platform guide pp. 2–3 · Applicant guide p. 4
03

The specialists

CLOUD RUN / AI SERVICES+

Separate services handle requisitions, ingestion, transcription, face comparison, interview sessions and evaluation. Dialogflow CX and the documented agent integration coordinate dialogue; OpenRouter is used for job-description and question synthesis.

Why separate services?
Each capability has a defined request and response contract instead of exposing every integration directly to the browser.
AI in context
Role requirements, question rubrics and candidate responses give the models task-specific context.
Platform guide pp. 4–5, 7 · Applicant guide pp. 6, 10
04

The evidence

CLOUD STORAGE / VECTOR INDEX+

Resume documents and interview media are stored in Google Cloud Storage. Indexed resume content supports semantic retrieval. Time-limited signed URLs let authorized reviewers access files without making the storage bucket public.

Search path
Resume → extraction → vector indexing → role-based retrieval → match evidence and gaps.
Media path
The server provisions a resumable upload session; recording data goes directly from the browser to Cloud Storage.
Platform guide pp. 4, 6, 8 · Applicant guide p. 8

The exception to the BFF data path: authorized video uploads travel directly to storage, so large recordings do not pass through the application server.

02 / Follow an interview

01
Entry & eligibility

A link. A session.
A verified starting point.

The candidate signs in through a Firebase email link. The BFF exchanges the resulting ID token for a server-managed session cookie and checks interview eligibility.

What crosses the boundary?

A short-lived Firebase ID token is sent to the login function. Firebase Admin issues an HttpOnly session cookie; protected server functions validate it, including revocation checks. The applicant specification describes a five-day session lifetime.

Applicant guide pp. 3–4
02
Hardware & active liveness

Check the setup.
Establish presence.

Camera and microphone permissions are checked before randomized smile, blink and head-movement challenges. A captured selfie and reference ID are passed to the face-comparison service.

How do the browser checks work?

The documented face-api integration runs landmark models in the browser. Eye aspect ratio detects blinking; relative landmark distances estimate head movement. These checks provide verification signals, not a guarantee of identity or fraud prevention.

Applicant guide pp. 3, 5
03
Voice, text & context

A conversation.
One turn at a time.

The candidate records a response, reviews it and confirms sending. Speech-to-text produces a transcript; the agent processes the message with session context and returns the next response.

Follow the audio round trip

Microphone → MediaRecorder → preview confirmation → BFF → transcription service → interview agent → response text → browser speech synthesis. The candidate portal describes adjustable voice settings and large subtitles; the recruiter platform also describes audio playback and Dialogflow audio responses.

Applicant guide p. 6 · Platform guide pp. 5, 8
04
Finalize & review

Close the session.
Keep the context.

When the candidate finishes or time expires, the flow stops media capture and finalizes the recording upload. The documented completion path includes transcript export and logout.

What does the reviewer receive?

The evaluator workbench brings together questions, transcripts, audio/video, rubric outputs and integrity signals. Reviewers add notes and a verdict, then export a candidate dossier. AI-generated assessments remain inputs to human review.

Applicant guide pp. 3, 8 · Platform guide pp. 8–10

01

Resume ingestion & semantic matching

+

Single or batch PDF/DOCX uploads link candidate records to a job. Recruiters can inspect stored files, select documents for indexing and query the resulting corpus against role requirements.

The specification describes cosine-similarity matching between job queries and resume chunks, alongside seniority inference, matched criteria and missing information. A match score is a retrieval signal—not a probability that someone will succeed in the role.

Upload → Parse → Index → Retrieve → Inspect evidencePlatform guide pp. 4, 6
02

Question generation & rubric calibration

+

Questions are associated with job IDs and can be added, edited or removed by recruiters. The AI-generation service uses the role description and required skills to draft questions, expected-answer criteria and rubric terminology.

A separate simulator lets teams preview introductions, question timing, transcription and grading behavior before use. The guide describes its telemetry as isolated from production candidate records.

Platform guide p. 7
03

Authentication & access control

+

Client sessions and service authorization are separate. Firebase Admin validates cookies; the BFF obtains destination-scoped IAM OIDC tokens for private Cloud Run services. HttpOnly, Secure in production and SameSite=Lax are documented cookie settings. These controls reduce specific risks; they do not constitute a complete security guarantee.

Super Admin
Roles, configuration and full hiring operations.
Recruiter
Jobs, ingestion, search, comparison and scheduling.
Interviewer
Evidence review, notes and verdict submission.
Viewer / Auditor
Read-only inspection and report downloads.
Platform guide p. 3 · Applicant guide p. 4
04

Integrity signals & human interpretation

+

The documents describe face matching, voice-analysis results and browser/camera telemetry. Candidate-side monitoring records events such as visibility changes, focus loss, face absence and additional faces, with periodic batching and mid-interview liveness checks.

The platform guide combines signals into a Trust Gauge. A flag is not proof of misconduct: environment, accessibility needs and technical failures can affect observations. Review the underlying evidence rather than treating an aggregate score as a hiring decision.

Platform guide p. 9 · Applicant guide p. 7; interpretation caveat added for this public walkthrough.
05

Recording & resumable cloud uploads

+

MediaRecorder combines camera and microphone tracks. The BFF creates a Google Cloud Storage resumable upload session and returns its upload URL; the browser transfers the recording directly to storage, with retry handling described in the guide.

This avoids routing large media bodies through the BFF. Completion and teardown coordinate upload finalization and media-stream shutdown. Browser close warnings and emergency sync handlers are documented, but abrupt closure or network loss can still interrupt a transfer.

Browser → BFF: authorize upload
BFF → Storage: create session
Browser → Storage: recording dataApplicant guide p. 8
06

Evidence review & candidate dossiers

+

Reviewers inspect transcripts against question prompts and rubrics, replay recordings, examine session events and add notes. The guide describes weighted scoring controls and a final reviewer verdict.

Client-side PDF generation packages the candidate summary, question-level evidence, integrity signals and reviewer notes. Scratchpad notes are documented as browser-local storage, distinct from submitted evaluation records; device access and retention need separate consideration.

Platform guide pp. 8, 10
07

Data boundaries & responsible deployment

+

The applicant guide specifies that biometric captures remain in volatile browser memory rather than localStorage, sessionStorage or IndexedDB before transmission for comparison. The platform guide describes signed URLs for access to stored resumes and recordings.

The supplied material does not establish a complete retention schedule, independent fairness evaluation, consent policy or compliance certification. These require explicit organizational policies and validation; this page makes no claim that they are already in place.

Applicant guide p. 5 · Platform guide pp. 4, 8; scope limitations identified from the supplied material.
08

Build, test & deployment

+

The documented application uses pnpm, TypeScript, Vitest, ESLint and Prettier. A production build emits the Nitro server bundle. Firebase App Hosting and a multi-stage Docker deployment on Cloud Run are described deployment paths.

Server credentials and database connection details stay out of client-prefixed environment variables. The website you are reading is a separate plain HTML/CSS/JavaScript site hosted on Render—not the candidate portal or its backend.

Application: test → check → build → server deployment
Marketing site: static files → Git → Render CDNPlatform guide p. 12 · Applicant guide p. 11
